# ProceduralDungeon icon

## What this is

The mod's icon: `icon.png` — 1024x1024 RGB PNG, 1 066 506 bytes,
sha256 `787daf6849691fac6839a34062062db8b670133c4220e428d36df1d6e7952618`.

It is a deterministic **radial composite of 20 in-game captures**: the same procedural
dungeon, generated once per theme, rendered orthographically, then cut into 20 equal
18-degree wedges arranged clockwise from the top.

## How it was made

### 1. The dungeon (real Minecraft)

The 20 themes were generated by a real Minecraft client (26.2, Fabric Loader, ProceduralDungeon’s
own `/generatedungeon` command) on an isolated Xvfb display `:247` with its own PulseAudio
null sink `dungeon2_capture`. The dungeon layout RNG is `WorldgenRandom` seeded from the
world seed plus the chunk, so one winning chunk position produces the same layout in every
theme:

| | |
|---|---|
| World | `Round3 Tall Dungeon`, flat generator, seed `20260910`, datapack `round3-canonical-pools`, `random_tick_speed = 0` |
| Command | `/generatedungeon <theme> 5 20`, executed once per theme at the winning chunk |
| Winning model | `cx120cz0y200t5d20` — 1148 pieces, 364 376-391 blocks, bounding box `[1848, 129, -72] .. [1992, 261, 72]` (145x133x145 blocks) |
| Proof of identity | `evidence/geometry-verification.json`: identical piece count and bounding box for all 20 themes; the ≤ 0.44 % voxel symmetric difference is a palette effect (a theme mapping a block to lava/water loses that voxel from the structural set) |
| Seed search | 35 candidate chunks driven in-game, measured straight out of the saved region files; `evidence/seeds-report.json`, `evidence/search-log.json`, `evidence/search-progress.log` |

Per theme, the region files holding the dungeon were copied out of the game save into
`worlds/<theme>/` (`scripts/drive_themes2.py`); `scripts/make_final_world.py` had prepared
the fresh final world first, and `scripts/drive_search.py` / `scripts/analyze_candidates.py`
did the seed search. The client-side capture session is recorded in `evidence/generation-log.json`,
`evidence/final-world-setup.json` and `evidence/cleanup.json`.

### 2. The per-theme images (headless Chunky)

`scripts/chunky_render2.py` renders each theme's staged world with Chunky
`2.5.0-SNAPSHOT.478.g527cb4a` standalone, headless, **PARALLEL (orthographic)** projection:

| | |
|---|---|
| Camera | position `(2107.2833, 337.476, -186.2835)`, yaw 45°, pitch 30° (Chunky radians: `-1.0471975511966`), shift `(3.5716, -7.524, -2.5717)` solved from the measured world-space silhouette, `fov` 236.08 blocks, `yClip 129..319` |
| Canvas | 1600 px, `spp 64`, 196 chunk-list entries, margin fraction 0.07, output 1024 |
| Reference | an identical render of `worlds/_empty` for the sky mask |
| Crop | the measured content box padded on the odd-parity axis so the square crop has exactly equal margins within each axis, then downsampled to 1024x1024 → `renders/crops/<theme>-chunky-ortho-1024.png` |

`evidence/chunky-render-log.json` and `evidence/chunky-render-log-approved-run.json` record
every render of both batches with camera, crop side, margins and command.

**The 20 `renders/crops/*-chunky-ortho-1024.png` files in `provenance/` are those per-theme
images** — 0.82 to 1.19 MB each (20.8 MB in total), one per theme, all with identical geometry.

### 3. The composite

`scripts/build_composite2.py` (`build_radial`) writes the delivered file:

* canvas 1024x1024; 20 equal wedges of 18°;
* wedge index for pixel `(x, y)` is `int(atan2(x + 0.5 - 512, -(y + 0.5 - 512)) % 360 // 18)`
  — i.e. wedge 0 points straight up and the wedges run **clockwise**;
* every pixel of wedge *k* is a **direct pixel copy at the same coordinates** of theme *k*'s
  own 1024 crop: no blending, no sampling, no colour grading;
* the theme order is the round-3 order, a fixed list:
  `cobblestone, deepslate, sculk, desert_tomb, lush, dripstone, frozen, ocean_ruin,
  amethyst_geode, copper, stronghold, nether_wastes, crimson_forest, warped_forest,
  basalt_deltas, soul_sand_valley, nether_fortress, bastion, end_stone, end_city`.

Two alternative orderings were also produced in that session and were **not** chosen
(rainbow by measured hue, and a max-contrast cycle solved by simulated annealing with seed
20260913); their numbers are in `evidence/ordering-report.json`.

## How to regenerate

The session ran with working directory `<round3>/captures-dungeon2`. The full chain needs
the game client, the Chunky jars and the worlds; the *composite* step needs only the 20
per-theme images:

```sh
cd captures-dungeon2

# --- full chain (needs Minecraft 26.2 + the mod jar + Chunky 527cb4a + a display) ---
python3 scripts/setup_runtime.py                       # runtime + argfile
sh   scripts/launch-dungeons2.sh                       # client on :247, own audio sink
python3 scripts/drive_search.py                        # 35-candidate seed search
python3 scripts/make_final_world.py                    # fresh world for the winner
python3 scripts/drive_themes2.py                       # /generatedungeon per theme + region extraction
python3 scripts/chunky_render2.py model                # solve camera/silhouette
python3 scripts/chunky_render2.py stage                # stage scenes
python3 scripts/chunky_render2.py all                  # 1600 px render + 1024 crop per theme
python3 scripts/verify_geometry2.py                    # prove the 20 layouts identical

# --- the composite alone (needs only provenance/renders/crops/*.png) ---
PYTHONPATH=/nix/store/4v9j9wbzyhrlx9980ygbr812313mazy0-python3.13-pillow-12.3.0/lib/python3.13/site-packages \
python3 - <<'PY'
import sys; sys.path.insert(0, 'scripts')
import build_composite2 as b, pathlib
b.build_radial(b.theme_order(), pathlib.Path('renders/composite/proceduraldungeon-all20-radial-theme.png'))
PY
```

`python3 scripts/build_composite2.py` runs the whole thing (all three orderings, contact
sheet, ordering comparison, `ordering-report.json`), but it first measures every theme's mean
colour from `renders/frames/<theme>.png`, so it also needs the 1600 px frames — which are
**not** shipped (see Notes). The snippet above builds the delivered theme-order radial
without them, because that ordering does not depend on the colour measurement.

## Notes

* **The per-theme images shipped here are the approved re-render, not the exact files the
  delivered icon was cut from.** The delivered `icon.png` is dated 2026-09-13 16:14 and was
  written by `build_composite2.py` from that day's crop batch. On 2026-09-14 the per-theme
  images were re-rendered (the "approved run") and `renders/crops/` was overwritten in place.
  `scripts/build_dimension_composite2.py` states it explicitly: *"renders/composite/
  proceduraldungeon-all20-radial-theme.png (round-3 theme order) remains the primary composite
  and was not rebuilt"*. Consequence: re-running `build_radial` on the shipped crop set
  reproduces the **identical construction, wedge geometry and theme order**, but not the
  identical pixels — measured against the delivered file, 54.8 % of pixels are identical, the
  sky is unchanged and the differences are confined to the structure area (a re-render at
  `spp 64` and a slightly different crop side). The original crop batch is not preserved
  anywhere.
* The 1600 px per-theme frames (`renders/frames/*.png`, 49 MB) are not shipped: they exceed
  the per-mod size budget, and the two composites that do read them only need them for the
  *rainbow* and *contrast* orderings, neither of which is the delivered icon.
* The wedge geometry is exact: the delivered file is a per-pixel assembly, so there is no
  interpolation anywhere in the composite step.
* `blockers.json` records two unreachable requirements of the original brief: no candidate had
  a perfectly square content bounding box (margins are exactly equal *within* each axis, not
  between axes), and in the proportional dimension ring the three sectors cannot sit exactly
  on the named directions.
* Two other composites (`proceduraldungeon-all20-radial-dimension-equalthirds.png`,
  `-dimension-proportional.png`) and a legend were produced in the later approved run; they are
  different deliverables and are not part of this icon.
